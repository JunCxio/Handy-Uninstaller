# Handy Uninstaller

Windows x64 桌面程序。使用原生 Win32 窗口，无第三方 Rust 依赖。发布后可直接运行单个 `handy-uninstaller.exe`。

## 构建

安装 Rust 工具链后，在项目目录执行：

```powershell
cargo build --release
```

输出文件：`target/release/handy-uninstaller.exe`。

应用图标已嵌入可执行文件。更换 `assets/app.ico` 后，先运行 `python tools/make_icon_object.py` 更新资源对象，再重新构建；`assets/app.svg` 是可编辑的原始图形。

## 功能范围

- 枚举 HKLM、HKCU 的 64 位和 32 位卸载注册项，以及当前用户的商店应用；通过“桌面应用”和“商店应用”页签切换。
- 显示应用名称、版本、发布者、来源、安装时间和可取得的程序图标；优先提取较大的原生图标，并以 24 像素绘制。点击列标题切换升序、降序，支持搜索和刷新。
- 操作区提供“撤销清理”“操作记录”、主题切换和刷新。浅色与深色模式选择保存在当前用户的 `HKCU\SOFTWARE\HandyUninstaller\DarkMode`。底部显示所选应用与版本，卸载操作仍从右键菜单进入。
- 启动卸载前显示实际命令，并重新读取传统程序的名称、卸载命令、发布者、安装位置、图标和 MSI 标记；确认期间若登记项变化则停止。PowerShell、注册表编辑器和无路径的系统卸载程序均从 Windows 系统目录定位，避免当前目录或 `PATH` 中的同名程序被误启动。
- 右键支持单项卸载和多选后的逐个卸载。桌面应用等待卸载进程及其子进程结束，确认卸载登记项消失后自动扫描残留；商店应用依次执行卸载命令，确认包系列不再安装后扫描残留。卸载、清理和刷新期间，列表及搜索、页签均不可操作。
- 右键菜单还包含强制删除、删除条目、注册表条目和安装文件夹。删除条目只删除卸载登记项；注册表条目会在注册表编辑器中定位到对应项。
- 强制删除及卸载后的残留扫描会列出可逐项勾选的候选项和匹配依据，并在执行前再次确认。桌面应用候选项包括明确的安装目录、指向该目录的快捷方式、名称完全一致的 AppData 或 ProgramData 目录、`Software\<发布者>\<应用名>` 注册表键及卸载登记项。不会把 `Software\<应用名>` 等可能是共享根的键列入候选项。确认后重新读取全部卸载登记项（包括列表中隐藏的系统组件）并重算候选项；如果新应用开始共用目录，停止清理该目录。目录必须避开系统和用户资料区域，并在清理前拒绝重解析点。卸载登记项最后清理；若前面的清理失败，则保留登记项。在预览或最终确认处取消，不会清理任何候选项。

卸载、删除条目和清理结果会写入当前用户的 `%LOCALAPPDATA%\HandyUninstaller\operations.tsv`，可通过顶部“操作记录”查看。Handy 清理的文件及快捷方式会暂存到原目录旁的 `.Handy-Uninstaller-Recovery`，其中的同编号 `.txt` 文件记载原路径；注册表键值保存在当前进程内。本次运行期间可按清理顺序逐次撤销；恢复时不会覆盖已重新出现的目标。关闭窗口前会提示确认，确认后永久删除隔离内容并丢弃注册表快照。异常退出后文件仍留在隔离目录，可按记录手工恢复；注册表快照无法跨进程恢复。撤销不包含第三方卸载程序的操作，也不恢复注册表项的自定义访问控制权限。若最终删除隔离内容失败，程序会显示保留路径供手动处理。

商店应用的枚举与卸载、快捷方式目标读取使用 Windows 自带的 PowerShell。商店应用图标从包清单解析，并由 Windows GDI+ 加载；包内没有可用图标时显示通用图标。商店应用没有传统卸载注册项，右键菜单中不适用的操作会禁用。商店应用卸载成功且同一包系列已不再安装时，残留候选项包括 `%LOCALAPPDATA%\Packages\<包系列名>`、当前用户的 `SystemAppData\<包系列名>` 以及 `ActivatableClasses\Package\<完整包名>` 注册表键；路径必须精确匹配并通过安全检查，清理前仍需用户勾选确认。

当前筛选和残留规则是基于 Geek 逆向证据的保守实现：要求 `DisplayName` 和 `UninstallString` 非空，排除 `SystemComponent=1` 和带 `ParentDisplayName` 的条目；尚未证明与 Geek 的所有显示条件及残留匹配规则完全一致。不会扫描 MSI 痕迹，也不会按模糊名称删除其他文件或注册表项。Geek 的商店应用注册表扫描还遍历多个共享区域，本程序只处理能按包标识准确归属的键。

安装时间读取桌面应用卸载登记项中的 `InstallDate`（`YYYYMMDD`）；登记项没有日期或商店包无法提供日期时留空。无法从现有系统数据可靠取得应用的累计使用时间，因此界面不显示该列，也不再写入使用时间记录。

REA 配合 Ghidra 对提供的 Geek Uninstaller 免费版进行了静态分析，确认其普通残留扫描经过安装目录、快捷方式、应用数据目录和注册表阶段；候选项的全部匹配条件仍未完全还原。Geek 官网将“专业版”链接到 CrystalIdea Uninstall Tool。对其官方便携版的静态分析表明，真正的“安装并跟踪”依赖 `CisUtMonitor.sys` 驱动与安装服务，跟踪文件和注册表事件，并在保存前过滤无效、重复及嵌套项目。本程序不提供安装监控；批量卸载和自动残留扫描也不宣称与专业版内部算法完全一致。

单元测试：`cargo test`。窗口验证使用 `python smoke.py target/release/handy-uninstaller.exe`，检查列表、图标列表、页签、搜索、主题、刷新、操作记录入口、撤销按钮和右键菜单，不启动卸载或删除。`python tools/test_recovery_flow.py` 使用唯一临时注册表项和临时目录验证候选依据、操作记录与撤销；设置 `HANDY_TEST_FINALIZE=1` 后运行同一脚本，可验证关闭时最终清理。测试需要允许写入当前用户注册表。另使用临时注册表项与模拟卸载命令验证了进程等待、列表锁定、取消后保留文件、确认期间新增共用目录应用时拒绝清理，以及列表刷新；未对真实应用执行卸载。
